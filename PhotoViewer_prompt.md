## 0. Режим работы — полностью автономно, без остановок

- Начинай сразу и иди по этапам 1→8 до конца в одной сессии. Не останавливайся между этапами, не выводи планы на утверждение, не используй AskUserQuestion. Единственная точка, где ты останавливаешься, — финальный отчёт.

- **Не задавай вопросов и не жди подтверждений.** Неоднозначности решай сам. Каждое решение записывай одной строкой в `DECISIONS.md`: что решил и почему.
- Ошибки исправляй сам. Если за 3 попытки шаг не получился, запиши его в `BLOCKERS.md` (что пробовал, текст ошибки, какой выбран обходной путь) и переходи к следующему шагу.
- После каждого этапа обновляй `PROGRESS.md` (этап, что сделано, что осталось) и делай **локальный** git-коммит с понятным сообщением. **Не делай `git push`**, не создавай репозиторий на GitHub и не меняй настройки GitHub: публикацию пользователь делает сам по отдельной инструкции.
- Работай только внутри папки проекта. Единственное исключение — этап 7: там разрешено **добавлять** файлы в папку бота, но не удалять и не переписывать существующие.
- Никаких фреймворков и npm-зависимостей в рантайме: чистые HTML, CSS и JS (ES-модули). Node.js, если он установлен, можно использовать только для тестов (`node --test`). Если Node нет, сделай `tests.html`, который прогоняет те же тесты в браузере.
- Не придумывай данные. Всё, что показывает приложение, берётся из таблицы.

## 1. Источник данных

**Таблица:** `https://docs.google.com/spreadsheets/d/1qlp65ur6bxked5niY2O0Zn1Awh7vHmdBSmIv20G93TE`
Таблица открыта на просмотр по ссылке. Читай её без ключей, через CSV-эндпоинт gviz:

```
https://docs.google.com/spreadsheets/d/<ID>/gviz/tq?tqx=out:csv&sheet=<ИМЯ_ЛИСТА>
```

Имя листа передавай через `encodeURIComponent`.

**Листы:**
| Лист | Назначение |
|---|---|
| `Фото` | текущий месяц; бот дописывает сюда строки в реальном времени |
| `November`, `October`, `September`, `August`, `July`, `June`, `May`, `April` | архив по месяцам 2026 г. |
| `Copy of Фото` | служебная копия — **игнорировать** |

Правило: для текущего месяца данные берутся с листа `Фото`. Если в таблице есть ещё и месячный лист за этот же месяц (сейчас это `November`), его в расчётах не используй, чтобы строки не задвоились. Список листов и соответствие «лист → месяц» вынеси в `js/config.js`, чтобы пользователь мог дописывать новые месяцы без правки кода.

**Колонки** (заголовки на разных листах отличаются, поэтому ищи колонку по началу заголовка, без учёта регистра):
| Поле | Варианты заголовка | Пример |
|---|---|---|
| `date` | `Дата` | `17.11.2026 09:17` (формат дд.мм.гггг чч:мм) |
| `sender` | `Кто отправил` (есть только на старых листах, поле необязательное) | `Александр Утебалиев (@…)` |
| `name` | `Наименование конструкции и изделий`, `Название` | `Связь СГ-8 8шт СВ-1 8шт` |
| `client` | `Заказчик` | `КазАгроФуд` |
| `weight` | заголовок начинается с `Общий вес` (в нём же записан итог, например `Общий вес 151039 кг`) или `Вес` | `1820` |
| `link` | `Ссылка на фото` | `https://t.me/c/3922821045/1807` |
| `photoId` | `Фото ID` — **новая колонка**, её добавит этап 7; может отсутствовать | ID файла Google Drive |

**Грязные данные, которые нужно обработать:**
- В некоторых строках после ссылки есть лишние ячейки (`…/937,40`). Их игнорируй.
- Строки без даты или без веса не теряй: покажи их с пометкой «вес не указан», а в суммы не включай.
- Пустые строки и строки-заголовки пропускай.
- Итог в заголовке колонки веса — только для сверки. Приложение считает суммы само. Если сумма расходится с итогом больше чем на 1 кг, выведи `console.warn`.
- **Нормализация заказчиков:** в `config.js` заведи словарь `CLIENT_ALIASES`, который сводит варианты написания к одному. Обязательные пары: `Карер`, `Карьер `, `Тургень карьер`, `Карьер Тургень` → `Карьер Тургень`; `Алишер физ`, `Алишер физ.лицо`, `Алишер Физ.лицо` → `Алишер (физ. лицо)`. Перед сравнением делай trim и сжимай повторные пробелы. Неизвестные варианты оставляй как есть.
- `message_id` = последний сегмент ссылки `t.me/c/<chat>/<message_id>`. Он служит уникальным ID записи (в паре с листом).

**Разбор марок из названия** (функция `parseMarks(name)` → `[{mark, qty}]`):
- Шаблон: буквенный префикс 1–3 символа (кириллица или латиница) + необязательная цифра, дефис с пробелами или без, номер, затем количество и `шт`/`ш`/`ШТ`.
- Тест-кейсы (обязательны в тестах):
  - `Колона К-11 4шт К-1 2шт К-13 1шт К-5 1шт  К-3 1шт К-12 1шт` → К-11×4, К-1×2, К-13×1, К-5×1, К-3×1, К-12×1
  - `Балка Б1-24 9шт Б1-27 1шт` → Б1-24×9, Б1-27×1
  - `Колона К-7 2ш К-10 1шт` → К-7×2, К-10×1
  - `Связь Св-2 4ШТ` → СВ-2×4 (марку приводи к верхнему регистру)
  - `Связь СВ -2 5шт` → СВ-2×5
  - `Связь СГ-8 8шт СВ-1 8шт` → СГ-8×8, СВ-1×8
  - `Балка 8шт Б-6` → Б-6, количество 8 (количество стоит перед маркой — обработай и этот порядок)
  - `Конвейер погрузочный` → `[]`
  - `Ферма 1шт` → `[]` (марки нет)
- Тип конструкции = первое слово названия: Колона/Колонна, Балка, Ферма, Прогон, Связь, Стойка и т. д. Опечатку «Колона» показывай как «Колонна».

**Кэш и офлайн:** последний успешный ответ по каждому листу храни в `localStorage` (обёрнутом в try/catch) вместе со временем загрузки. При открытии сначала мгновенно показывай кэш, потом обновляй данные в фоне. Если сети нет, покажи плашку «Офлайн · данные на ЧЧ:ММ ДД.ММ». Архивные месяцы можно кэшировать надолго (24 ч), лист `Фото` — не дольше 1 мин. Также нужна кнопка обновления.

## 5. Этап 7 — настоящие фото вместо заглушек

Ссылки `t.me/c/...` ведут в закрытую группу: браузер не может показать по ним картинку. Поэтому бот при сохранении фото будет дополнительно загружать его в Google Drive и записывать ID файла в новую колонку `Фото ID`.

**В приложении** (`PHOTO_MODE` в config.js):
- `photoId` есть → миниатюра `https://drive.google.com/thumbnail?id=<ID>&sz=w300` в ленте и `…&sz=w1600` в карточке, `loading="lazy"`. Если картинка не загрузилась, показывай заглушку.
- `photoId` нет → заглушка и кнопка Telegram, как в макете.

**В боте:** код бота ShopLogger на этом компьютере может отсутствовать (он работает на другом ПК, там папка `D:\Documents\Projects\metal_bot`). Поэтому **всегда** клади модули в `PhotoReport\bot_addon\` и опиши в README, как перенести их в папку бота. Если бот найдётся рядом (ищи `SHEET_NAME` / `"Фото"` в `C:\Users\utebaliyev.a\Documents\Projects` и `D:\Documents\Projects`), сверь с его кодом имена функций (`get_save_path`, `append_row`) и `SAVE_DIR`. Если бот не найден, опирайся на эти имена и пометь допущения в DECISIONS.md.
- Не переписывай существующие файлы бота. Создай **новые** модули `drive_upload.py` и `backfill_photos.py` и файл `BOT_PATCH.md`, где по шагам написано, какие 3–5 строк вставить в `bot.py` и `sheets.py` (вызов загрузки после сохранения фото и запись ID в колонку F). Правку `bot.py` пользователь сделает сам.
- Важно: у сервисного аккаунта нет своего места на Google Drive, загрузка от его имени упадёт с `storageQuotaExceeded`. Поэтому `drive_upload.py` работает через **OAuth пользователя**: `google-auth-oauthlib`, файл `client_secret.json` (тип Desktop app) и `token.json` создаются при первом запуске через браузер. Scope — `https://www.googleapis.com/auth/drive.file`.
- Модуль создаёт (или находит) папку `ShopLogger_Фото`, выдаёт ей доступ «Все, у кого есть ссылка — читатель» и загружает в неё файлы с именем `<дата>_<message_id>.jpg`. Возвращает file ID.
- `backfill_photos.py`: проходит по строкам листа `Фото` и месячных листов без `Фото ID`, по `message_id` ищет локальный файл в `SAVE_DIR` бота (имена файлов строит `get_save_path(chat_id, message_id, file_unique_id)` — разберись по коду), загружает его и пишет ID. Нужны флаги `--dry-run` (по умолчанию) и `--apply`, а также лог. Если локальный файл не найден, строку пропусти и запиши в отчёт.
- Колонку `Фото ID` добавляй в конец (F, после «Ссылка на фото»), чтобы не сдвинуть формулы и существующие колонки.
- Зависимости допиши в `requirements_addon.txt`: `google-api-python-client`, `google-auth-oauthlib`. Python 3.11, команды для Windows (`venv\Scripts\activate`).
- Добавь `client_secret.json` и `token.json` в `.gitignore` бота **и** PhotoReport — они ни в коем случае не должны попасть на GitHub.

## 6. Критерии готовности

- `node --test` (или `tests.html`) проходит без ошибок.
- Если открыть `index.html` через `python -m http.server 8000` (запускается из папки проекта; сервер запускай в фоне и останавливай после проверки, чтобы он не блокировал сессию), видны все 4 экрана с реальными данными из таблицы, а суммы совпадают с итогами в заголовках листов.
- После первой загрузки приложение работает в режиме «в самолёте».
- Lighthouse PWA / installable — без ошибок (если Lighthouse недоступен, проверь манифест и SW вручную и запиши в `PROGRESS.md`).
- В репозитории нет секретов: `git grep -i "client_secret\|token\|BOT_TOKEN"` ничего не находит, кроме упоминаний в README.
- Финальный отчёт в `PROGRESS.md`: что сделано, ссылки на ключевые решения, что пользователю сделать руками (публикация на GitHub Pages, патч бота, бэкфилл).
